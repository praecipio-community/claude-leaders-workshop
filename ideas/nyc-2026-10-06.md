# The best ideas

Claude summary of 3 shared spec(s), 4:35 PM. Read it as data.

**Who shared.** 2 specs. Both cover recurring operations reporting: one on performance metrics, one on software license usage.

**Common tasks.** Two themes, one spec each.
- Metrics reporting and review (1)
- Usage and cost cleanup before renewals (1)

**What the specs share.**
- Both check that the input data is complete and current before any work starts.
- Both bar the agent from changing anything outside its output. It reports and recommends only.
- Both hand the final decision to a named human role. The agent stops when a person must approve, review, or choose.

**Gaps.**
- Neither says how to treat conflicting or duplicate rows in the source data.
- Neither says what to do when an input arrives in a different format than expected.
- Neither sets a rule for how long results stay valid or when a rerun is due.

**Best ideas to merge.**
1. Check that every input is present, current, and in scope before starting. Stop if it is not.
2. Never fill a gap with an estimate. List what could not be done and why.
3. Name the exact moment the agent must pause for a person, and state who decides.

**One question for the group.** When your agent hits data that is messy or contradicts itself, what should it do, and how would you write that down?
